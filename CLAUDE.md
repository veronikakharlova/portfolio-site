# Портфолио-сайт Вероники Харловой

Личный сайт-портфолио UX/UI дизайнера. Простой статический сайт — HTML + CSS,
без фреймворков и сборщиков (React, Vue, Webpack и т.п. не используются).

**Живой сайт:** https://veronikakharlova.github.io/portfolio-site/
(GitHub Pages, репозиторий `veronikakharlova/portfolio-site`, ветка `main`).
Подробный статус каждого проекта и история сессий — в `NOTES.md`, прочитай
его в начале работы, если нужен контекст по прошлым правкам.

## Структура

- `index.html` — главная страница (шапка, hero, список проектов, опыт работы,
  образование, контакты)
- `projects/` — отдельные страницы для каждого проекта из портфолио.
  Каждая карточка проекта на главной странице ссылается на файл здесь,
  например `projects/messenger.html`
- `projects/project-template.html` — шаблон, на основе которого удобно
  делать новые страницы проектов (сохраняет общий дизайн сайта)
- `assets/` — обложки карточек проектов (`cover-*.jpg`) и общие ассеты сайта
  (портрет, og-картинка)
- Отдельная папка на каждый проект в корне (`messenger/`, `control/`,
  `retina-response/`, `deeplay/`, `gba/`, `yandex/`, `brokerage/`,
  `hackathon/`) — туда кладутся скриншоты именно этого кейса

## Дизайн-система

- Шрифт: Manrope (подключён через Google Fonts)
- Фон: кремовый `#FAFAFA`, альтернативный фон секций `#F5F6F8`
- Акцентный цвет: терракотовый `#B4573C`
- Текст: тёмно-серый `#1C1C1E`, приглушённый `#4A4A4E`
- Кнопки и теги — со скруглением в форме пилюли (`border-radius: 999px`)
- Карточки — скруглённые углы 18px, лёгкая тень при наведении
- Ширина колонки контента на страницах кейсов — `--max-width: 920px`,
  отступы контейнера `padding: 0 20px` (было 760px/24px, расширили по
  просьбе, чтобы скриншотам было просторнее)
- Все CSS-переменные (цвета, радиусы) объявлены в `:root` в начале `<style>`
  на каждой странице — страницы самодостаточны, общего CSS-файла нет,
  при изменении дизайна нужно повторять правку на всех страницах

## Переиспользуемые компоненты (страницы кейсов)

Каждая страница в `projects/` — самодостаточный HTML-файл со своим `<style>`,
но использует один и тот же набор классов. При добавлении нового кейса лучше
взять за основу не `project-template.html` (он минимальный), а один из уже
насыщенных кейсов — `messenger.html` или `retina-response.html` — и скопировать
нужные блоки:

- `.case-hero` + `.case-hero__back` (ссылка «← Все проекты» — living **внутри**
  `case-hero`, над тегами и заголовком, слева; в `.site-header` остаётся
  только имя)
- `.project-meta` — грид Роль/Команда/Сроки/Инструменты под hero-текстом
  (3 или 4 колонки в зависимости от того, есть ли что писать в «Сроки»)
- `.case-image`, `.image-row` (2 колонки), `.image-row--three` (3 колонки) —
  для скриншотов
- `.case-list` — буллеты вида `<strong>Заголовок:</strong> текст`
  (двоеточие, не тире)
- `.compare-table` / `.table-scroll` — таблицы сравнения
- `.screen-block` — блоки «было → почему изменила → стало» для реальных
  итераций процесса
- User flow — **не растровая картинка**, а либо диаграмма из HTML/CSS
  (`.flow`, `.flow__steps`, `.flow__branches`, см. паттерн в retina-response.html
  до правки) либо, если у пользователя уже есть готовая отрендеренная
  диаграмма (Mermaid-экспорт и т.п.) — используй её как есть, обрезав
  и оптимизировав, а не пересобирай вручную

## Правила при работе над сайтом

- Сохранять единый визуальный стиль между index.html и страницами в projects/
- Мобильная адаптивность обязательна — проверять на ширине экрана ~375px
- Не использовать внешние JS-фреймворки без явной просьбы
- Настоящий контент проектов (описания, скриншоты) добавляется постепенно —
  если данных не хватает, спрашивать, а не придумывать факты о проектах
  (цифры, цитаты, даты). Реальные скриншоты и текст с сайтов клиентов —
  предпочтительнее сгенерированного текста
- **Стиль текста кейсов**: от первого лица, по-деловому, без
  самооправдательных вставок вроде «это стоит сказать прямо, а не скрывать»
  или «и это тоже решение» — просто факты. Не злоупотреблять длинным тире
  (—): где просится обычное предложение через точку, запятую или
  двоеточие — используть его, а не тире
- **Скриншоты**: сырые/неиспользуемые исходники (полноразмерные экспорты,
  презентации, PDF) добавляются в папку проекта, но заносятся в `.gitignore`
  (см. существующие записи `/messenger/...`, `/control/...` и т.д.) — в git
  и на живой сайт попадают только обработанные файлы `web-*.jpg`, реально
  использованные в HTML. При добавлении новых картинок — сжимать
  (`PIL`/`Image.resize` + `JPEG quality~87`) и проверять, что все `src=`
  в HTML резолвятся в реальные файлы (`git status`/`find` перед коммитом)

## Деплой

Сайт живёт на GitHub Pages. Локально `gh` (GitHub CLI) не установлен
постоянно — в новой терминальной сессии его нет в `PATH`, поэтому в начале
работы с деплоем:

```bash
mkdir -p /tmp/gh-install && cd /tmp/gh-install && \
curl -sL -o gh.zip https://github.com/cli/cli/releases/download/v2.96.0/gh_2.96.0_macOS_arm64.zip && \
unzip -q -o gh.zip
GH="/tmp/gh-install/gh_2.96.0_macOS_arm64/bin/gh"
"$GH" auth status   # токен уже сохранён в Keychain — авторизация не нужна
"$GH" auth setup-git
```

После этого обычный `git add` / `git commit` / `git push origin main`
публикует изменения. Пересборка GitHub Pages занимает 1-3 минуты — проверять
через `"$GH" api repos/veronikakharlova/portfolio-site/pages/builds/latest`.
